# Milestone 5: offline prediction research

Run `php artisan astra:backtest` after deploying the corrected `ohlc-v2` engine. Then run `php artisan astra:train-prediction` (optional `--backtest-id=123`). The command requires at least 60 closed trades with entry-time RSI and relative volume. It uses the earliest 75% of those trades for training and the latest 25% for a single chronological holdout. The baseline probability is the training win rate with Laplace smoothing. Four RSI/relative-volume bins are shrunk toward that prior with a 20-observation weight.

The outcome label is **positive net P&L after modeled fees/slippage**, not target-before-stop. The Brier score compares the held-out model against a training-only prior. The API `GET /api/research/predictions` and dashboard Prediction Lab expose metrics and observed calibration bins. Saved model versions remain `observation`, `approved_at=null`. No prediction is eligible for execution; the existing ProbabilityGate remains fail-closed for unapproved predictions. No external Python service, live inference, scheduled learning, promotion, or model-registry approval endpoint is included.

**Important:** The source trading strategy and historical data have already been inspected. This is an exploratory holdout, not a pristine independent validation set. More representative data, embargoed purged walk-forward validation, calibration by regime, confidence intervals, transaction-cost robustness and independent review remain necessary. Running the command repeatedly on the same backtest does not improve a model.

## Frozen validation and paper-only approval

Collect a **new, later and non-overlapping** BTCUSDT hourly dataset after the source backtest's end. Save a standard corrected `ohlc-v2` backtest for that later period, with at least 40 closed trades containing valid entry features. Run `php artisan astra:validate-prediction MODEL_ID NEW_BACKTEST_ID`. This freezes the model's original training buckets and prior, rejects matching dataset hashes and overlapping time windows, and records later-period Brier score versus the frozen prior, calibration mean absolute error and sample count. The mechanical pass gates are ≥40 trades, better Brier than the prior, and calibration error ≤0.10. These are screening criteria, **not proof of statistical significance or independent data provenance**.

An operator may run `php artisan astra:review-prediction MODEL_ID approve --confirm` only after validation passes. This sets `paper_approved` for observation only; it does **not** set the existing execution ProbabilityGate's calibration flag, enable execution or promote any strategy. To roll back, run `php artisan astra:review-prediction MODEL_ID revoke --confirm`. New validation revokes previous paper approval pending review. The dashboard shows validation evidence and status. There is deliberately no browser-accessible approval endpoint.

Important: New backtest dates/hash alone cannot prove independent data provenance. Do not create a nominally later validation set by selecting or reusing candles that were already inspected during model development. Testnet order integration and live execution remain locked regardless of model status.
